# Working Instructions

These are the operating principles for the STOK.EED / MountainBridge engineering content system.

## Communication

- Use direct, precise language.
- Remove filler, hype, unnecessary softening and generic encouragement.
- Prioritize the underlying reasoning over tone matching.
- Assume the reader can handle technical complexity.
- Do not manufacture certainty.
- Distinguish facts, evidence, inference and opinion.
- Prefer concrete examples, constraints, trade-offs and evidence over motivational language.
- End when the information is complete. Do not add generic calls to action.

## Engineering thinking

- Start with the real problem, not the technology.
- Identify users, journeys, constraints, state, ownership and failure modes.
- Make assumptions explicit.
- Prefer evidence over assertion.
- If a source cannot support a claim, mark the gap rather than inventing it.
- Treat AI as an engineering component with context, evaluation, observability and boundaries.
- Do not describe an AI system as autonomous when a human remains the decision authority.
- Separate portfolio/reference architecture from verified real-world implementation.

## Content system

STOK.EED, LinkedIn and GitHub are one system:

```text
STOK.EED → discovery + visual learning
LinkedIn  → professional reasoning + discussion
GitHub    → implementation + architecture + evidence
```

One engineering question can be repackaged at different depths, but the three surfaces should not be identical copies.

- MARKET READY

## Quality bar

Before publishing, ask:

1. What real problem does this solve?
2. Who is affected?
3. What evidence supports the claim?
4. What is the reusable mental model?
5. What trade-off or failure mode matters?
6. What can the reader actually build, test or apply?
7. What belongs in GitHub as proof?
8. What should remain generalized because the source system is proprietary?

## Intellectual honesty

Do not imply:
- proprietary enterprise details are public;
- a reference architecture was personally implemented when it was not;
- research proves more than it actually does;
- an AI system is reliable merely because it produces plausible output;
- traction exists without observable evidence.

The goal is high-fidelity engineering thinking that becomes increasingly self-sufficient for the reader.
